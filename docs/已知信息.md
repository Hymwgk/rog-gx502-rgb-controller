项目背景
========

我正在把 ASUS ROG GX502 笔记本的原装逐键 RGB 键盘独立出来，用 STM32 控制原键盘背光。

当前目标：
先编写一个底层 RGB 背光驱动程序，能够：
1. 初始化键盘背光硬件；
2. 驱动 MBIA045 LED Driver；
3. 控制 GCLK / DCLK / SDI / LE；
4. 控制 CTRL0~CTRL7；
5. 最终逐步实现单色点亮、单个区域点亮、RGB、逐键控制以及动画效果。

目前不要直接假定 CTRL0~CTRL7 的扫描规律。
驱动应模块化，方便后续实验逆向。



一、原键盘主板 FPC 接口
======================

原 ASUS GX502 主板到 Keyboard Backlight 的接口为 20 Pin FPC。

已根据原理图确认引脚如下：

Pin 1  = LE_PWM1R       -> LE
Pin 2  = DCLK_PWM1G     -> DCLK
Pin 3  = SDI_PWM1B      -> SDI
Pin 4  = GCLK_PWM2R     -> GCLK

Pin 5  = KB_LED_TYPE    -> 键盘类型检测信号，暂时只读/保留，禁止主动推挽输出

Pin 6  = +3VA_DSW_Perkey -> KB_3V3

Pin 7  = +5VS_LED_KB     -> KB_5V
Pin 8  = +5VS_LED_KB     -> KB_5V
Pin 9  = +5VS_LED_KB     -> KB_5V

Pin 10 = GND
Pin 11 = GND
Pin 12 = GND

Pin 13 = LED_CTRL0
Pin 14 = LED_CTRL1
Pin 15 = LED_CTRL2
Pin 16 = LED_CTRL3
Pin 17 = LED_CTRL4
Pin 18 = LED_CTRL5
Pin 19 = LED_CTRL6
Pin 20 = LED_CTRL7

连接器另外有 SIDE1 / SIDE2 外壳焊盘，目前 PCB 上接 GND。
这一点不是驱动软件需要处理的。



二、当前 STM32 引脚分配
======================

当前硬件原理图：

LE   -> PA4
DCLK -> PA5
GCLK -> PA6
SDI  -> PA7

也就是说，目前计划：

PA5 = SPI1_SCK   -> DCLK
PA7 = SPI1_MOSI  -> SDI
PA4 = GPIO       -> LE

PA6 = GCLK
GCLK 最好使用 STM32 Timer 硬件连续输出，而不是软件 bit-bang。

CTRL0~CTRL7：
分别接 STM32 GPIO。
具体 GPIO 名称请从现有工程 / CubeMX 配置中获取，不要在驱动内部硬编码。

KB_LED_TYPE：
作为 GPIO input 或暂时不用。
不要配置为 push-pull output。



三、键盘上的 LED Driver
======================

键盘 PCB 上发现：

3 颗 MB1A045G

经过资料确认，其实际型号应属于：

Macroblock MBIA045 系列
完整 QFN 型号很可能为 MBIA045GFN

它是：
16-channel constant-current LED driver

每颗芯片有 16 个恒流 PWM 输出。

键盘上一共有 3 颗：

3 × 16 = 48 个恒流 LED 输出通道。

因为这是逐键 RGB 键盘，48 通道不足以直接驱动全部 RGB LED，
所以键盘内部显然存在复用 / bank / matrix scan。

CTRL0~CTRL7 很可能参与这种复用，但目前尚未实验确认。

重要：
不要在第一版程序中假定：
CTRL0 = Row0
CTRL1 = Row1
...
CTRL7 = Row7

需要先提供方便实验扫描 CTRL 的 API。



四、MBIA045 接口
================

MBIA045 不是 I2C 设备。

它使用类似串行移位寄存器的接口：

SDI   = Serial Data Input
DCLK  = Data Clock
LE    = Latch Enable / Command control
GCLK  = Grayscale Clock

SDI 数据由 DCLK 传输。

GCLK 用于芯片内部 PWM 灰度计数。

建议硬件实现：

STM32 SPI:
    MOSI -> SDI
    SCK  -> DCLK

STM32 GPIO:
    -> LE

STM32 Timer:
    -> GCLK

GPIO:
    -> CTRL0~CTRL7



五、MBIA045 数据能力
====================

每颗 MBIA045：
16 个输出通道。

支持 PWM grayscale。
资料显示支持 16-bit / 10-bit PWM 模式。

如果使用 16-bit 灰度模式：

每颗芯片一组完整 PWM 数据：

16 channels × 16 bit
= 256 bit

3 颗芯片如果串联：

48 channels × 16 bit
= 768 bit
= 96 bytes

注意：
目前“3 颗 MBIA045 是否通过 SDO -> SDI 串联”高度可能，但还没有通过万用表确认。

因此代码架构不要死锁为 3 芯片级联。

建议：

#define MBIA045_CH_PER_IC 16
#define MBIA045_NUM_IC    3

并把 NUM_IC 做成可配置参数。



六、MBIA045 LE 命令机制
=======================

MBIA045 的 LE 不只是普通 SPI CS。

根据 MBIA045 datasheet，
LE 为高期间出现的 DCLK 上升沿数量用于区分命令。

目前已知重要命令：

LE High + 1 DCLK rising edge
    -> Data Latch

LE High + 3 DCLK rising edges
    -> Global Latch

LE High + 5 DCLK rising edges
    -> Read Configuration

LE High + 11 DCLK rising edges
    -> Write Configuration

LE High + 15 DCLK rising edges
    -> Enable Write Configuration

因此：
不要把 LE 当普通 NSS 使用。

最好实现专门函数，例如：

mbia045_le_command(uint8_t clocks);

然后：

mbia045_data_latch();
mbia045_global_latch();
mbia045_read_config();
mbia045_write_config();
mbia045_enable_write_config();

具体时序一定按照 datasheet 实现。



七、GCLK
========

GCLK 是灰度 PWM 的工作时钟。

不要使用 while 循环不断 HAL_GPIO_TogglePin()。

应优先用：

STM32 Timer PWM / Output Compare

连续输出 GCLK。

当前 GCLK 引脚：
PA6

需要根据具体 STM32 型号检查：
PA6 可以复用哪个 TIMx_CHy。

如果 PA6 无法合理输出 Timer clock，再修改硬件/引脚配置。

GCLK 频率第一阶段不要直接拉到 datasheet 极限。

建议先提供：

mbia045_gclk_start(freq_hz);
mbia045_gclk_stop();

初期从较低频率实验，例如：
100 kHz
500 kHz
1 MHz
然后逐步提高。

datasheet 的 MHz 级最大频率只代表芯片能力，不代表必须使用最大值。



八、CTRL0~CTRL7
===============

这八个引脚来自 ASUS 主板：

LED_CTRL0
LED_CTRL1
LED_CTRL2
LED_CTRL3
LED_CTRL4
LED_CTRL5
LED_CTRL6
LED_CTRL7

根据整个结构推测：

3 × MBIA045
= 48 PWM current outputs

8 × CTRL
= 可能的 bank / row / group scan

一种可能的拓扑是：

16 个 RGB LED / bank
× 3 colors
= 48 driver channels

再乘 8 bank：

16 × 8
= 最大 128 个 RGB 键位

这在数量上非常合理。

但是：

！！！这只是当前推测，不是已经确认的事实！！！

驱动程序第一阶段应提供：

keyboard_ctrl_set(index, level);
keyboard_ctrl_all_off();
keyboard_ctrl_only(index);
keyboard_ctrl_set_mask(uint8_t mask);

方便逐个测试：

CTRL0 ON
CTRL1 ON
...
CTRL7 ON

并观察哪些按键被选中。



九、供电
========

键盘背光有两路电源：

KB_3V3
    -> 逻辑电源

KB_5V
    -> LED / 功率电源

STM32 GPIO 为 3.3V logic。

所有控制信号：
LE
DCLK
SDI
GCLK
CTRL0~CTRL7

均按照 3.3V 逻辑处理。

程序初始化时：
建议先关闭所有 CTRL，
停止 GCLK，
LE/DCLK/SDI 设置到安全状态，
最后再开始初始化 LED Driver。

避免上电瞬间全亮。

十三、未知项 / 禁止自行假定
===========================

目前尚未确认：

1. 三颗 MBIA045 的具体级联顺序。
2. 三颗 MBIA045 是否确实 SDO -> SDI 串联。
3. 48 个输出通道和 RGB LED 的物理映射。
4. CTRL0~CTRL7 的真实功能。
5. CTRL 有效电平是 HIGH 还是 LOW。
6. CTRL 是直接逻辑输入还是驱动 MOSFET。
7. 键盘实际使用 MBIA045 10-bit 还是 16-bit PWM。
8. 原厂 MBIA045 configuration register 的具体配置值。
9. KB_LED_TYPE 的电气意义。

因此请：

优先完成底层驱动和实验工具，
不要凭猜测把这些信息写死。



十四、安全要求
==============

为了避免烧键盘：

1. 上电后所有 CTRL 默认 inactive。
2. PWM brightness 默认 0。
3. GCLK 默认关闭。
4. 初始化完成后才允许开启输出。
5. 初期测试不要所有 LED 满亮。
6. 单通道测试从较小 PWM 值开始。
7. 提供 emergency off 函数：

KeyboardRGB_EmergencyOff()

立即：
关闭 CTRL0~CTRL7
停止 GCLK
输出数据清零

8. 不要修改 MCU 其它已有外设配置。
