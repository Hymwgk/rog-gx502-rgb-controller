# 代码结构与扩展约定

目录按固件、配置、电脑端工具、测试、资料分开。STM32 的公共接口集中在 `firmware/include/`；实现按职责放入 `firmware/src/`，避免把实验代码、动画参数和 GPIO 寄存器操作混在一个文件里。

| 层 | 当前职责 | 以后修改的位置 |
| --- | --- | --- |
| app | 初始化及测试模式入口 | 增加命令入口、串口选择模式 |
| effects | 呼吸曲线、斜向波浪、颜色循环及各播放路径的持续刷新 | 增加灯效类型、公共播放策略 |
| keyboard | 实测灯位、CTRL 选择、RGB 数据组织 | 补充逐键 API 与完整映射 |
| drivers | MBIA045 数据传输、LE 命令、global latch | 芯片协议及发送优化 |
| board | 实际引脚、GPIO 寄存器、MSI 与 GCLK | 更换控制板或时钟来源 |

电脑端 JSON 配置通过 `tools/scripts/effect_profiles.py` 校验，转换为 `build/effect_config.h` 的 C 常量。配置存放在 `configs/effects/`，不参与底层芯片驱动；每次构建选择一个配置，同时保存固件旁的实际参数 JSON。电脑端工具直接操作构建或烧录，STM32 不解析文件。

增加同类呼吸模式只需复制配置、更换名称与参数。增加新的动画类型时，再扩展配置校验和 effects 播放逻辑。若未来多个灯效共用不同的数据更新路径，应把持续刷新拆成独立的调度模块；目前由 effects 统一维护，避免提前添加无实际用途的框架。逐键不同颜色使用独立的 wave 刷新路径，已通过逐组不同灰度帧播放斜向波浪；构建阶段生成颜色查找表和各灯位的到达时间，避免 MCU 逐像素除法拖慢刷新。

频闪修复属于播放引擎的约束：持续扫描、显示期间发送下一帧、仅在最终锁存附近暂停 GCLK、每组选通覆盖一个完整的 1024 GCLK 子周期、灰度为 64 的倍数。新增配置不得随意绕过这些约束。原始现象、修复与用户确认见 [KEYBOARD.md](KEYBOARD.md#呼吸灯亮度高峰频闪修复)。

根目录四个命令脚本保留为薄入口，脚本实际路径位于 `tools/scripts/`，项目根目录由脚本自身位置计算。构建明确列出源码和链接脚本，不依赖调用时的工作目录或递归搜集源码。仅 `tools/linux/` 被作为外部工具链忽略，`tools/scripts/` 应纳入版本控制。

构建结果、相机照片和 ELF 快照在 `build/`，与源代码分开。配置本身可复现参数；要求跨代码版本保持完全相同的行为时，还需保存对应 ELF。接线和实测记录放入 `docs/`，键盘参考图片放入 `assets/`。

斜向波浪额外使用 32 MHz 系统时钟和快速 GPIO 串行循环；呼吸保留已验证的 MSI 时钟。只有 board 层访问 GPIO/时钟寄存器；drivers 层负责数据锁存格式，effects 层负责位置投影、渐变查表和组间调度。波浪在编译时要求实测的三芯片布局，运行诊断变量记录工作量与超时次数。
