# GX502 键盘背光接口与验证状态

资料来源为控制板原理图与项目中的 `已知信息.md`。控制板 J3 为 22 Pin 接口，原 ASUS 主板到键盘背光板的接口为 20 Pin；两者引脚号不同，不能直接对照插接。

| 信号 | STM32L051 引脚 | 控制板 J3 | 原主板 20 Pin FPC |
| --- | --- | ---: | ---: |
| LE | PA4 | 4 | 1 |
| DCLK | PA5 | 2 | 2 |
| SDI | PA7 | 3 | 3 |
| GCLK | PA6 | 5 | 4 |
| KB_LED_TYPE | 资料未确认 MCU 引脚 | 6 | 5 |
| KB_3V3 | 电源 | 1 | 6 |
| KB_5V | 电源 | 7–12 | 7–9 |
| GND | 电源地 | 21、22 | 10–12 |
| CTRL0–CTRL7 | PB0、PB1、PB8、PB9、PB10、PB11、PA9、PA10 | 13–20 | 13–20 |

键盘上有三颗标记为 MB1A045G 的芯片，按现有资料应属于 MBIA045 系列。每颗有 16 个恒流输出。数据手册定义了 16 位默认灰度格式、16 次数据锁存、1 次全局锁存，以及 LE 高电平期间 DCLK 上升沿数量对应的命令。[MBIA045 数据手册](https://www.believesrl.com/system/uploads/attachment/data/7780/59426983/MBIA045_Datasheet_VA.00-EN.pdf)；[应用说明](https://www.believesrl.com/system/uploads/attachment/data/7868/2948308/MBIA045_Application_Note_VA.00-EN.pdf)。

MCU 的 [STM32L051C8 数据手册](https://www.st.com/resource/en/datasheet/stm32l051c8.pdf) 确认 PA5=SPI1_SCK、PA7=SPI1_MOSI、PA6=TIM22_CH1（AF5）。当前代码使用 GPIO 生成需要精确 LE 时序的 SDI/DCLK，TIM22 输出 GCLK。`board.c` 是引脚映射的唯一位置；`mbia045.c` 不包含 STM32 引脚号。

## 尚未证实

- 三颗芯片是否 SDO→SDI 级联及级联顺序。`MBIA045_NUM_IC` 可在编译时配置，`mbia045_send_frame()` 目前实现 16 位三级级联格式。
- CTRL0–CTRL7 的功能和有效电平。API 中的 `level` 是原始 GPIO 高/低电平，未定义为“开/关”。初始化及 emergency off 时 CTRL 引脚设为高阻；若实际电路缺少外部偏置，高阻本身不保证灯完全关闭。
- 单 CTRL 高电平下的键位与 RGB 映射已通过摄像头扫描建立，见 [KEYMAP.md](KEYMAP.md)。多 CTRL 同时选通和动态矩阵刷新尚未验证。
- 键盘实际配置寄存器及 10/16 位灰度模式。代码默认按芯片上电默认的 16 位模式送帧，未擅自改写配置寄存器。
- `KB_LED_TYPE` 到 STM32 的实际走线。软件保持该引脚未配置为推挽输出。

## 后续板上验证

先观察初始化后的 LE/DCLK/SDI/GCLK 和 CTRL 电平，再以低亮度分别尝试明确的 CTRL 电平及单一原始通道，逐项记录点亮的键和颜色。由于用户暂不接串口，当前主程序不会自动运行扫描；`keyboard_rgb_probe()` 提供单步测试入口，之后可接入串口命令或调试器调用。不要从当前资料推断 CTRL0=第一行或三颗芯片分别对应 RGB。

动态测试：同一原始通道 0、灰度 1024、GCLK 请求 100 kHz，CTRL0 与 CTRL2 每秒交替选通。实测 C 键与空格键轮流亮起，没有其他键误亮。由此可确认当前 GPIO 串行传输、LE 锁存、TIM22 GCLK 和这两路 CTRL 的组合能驱动键盘背光。其他 CTRL 及键位映射仍待逐项实测。

2026-10-10 摄像头补充验证：已采集 CTRL0–7 高电平、通道 0–47 的全部 384 个组合，定位 88 个按键的 109 个灯位，确认每个灯位的通道 n/n+16/n+32 对应红/绿/蓝。19 个灯位未检测到亮灯；宽键包含多个灯位。此前 CTRL0/通道1 的 Fn 已明确为右 Fn。完整表、测试条件及限制见 [KEYMAP.md](KEYMAP.md)。扫描结束后已烧录并校验原 C 键亮度循环固件。

全键盘呼吸测试：`breathe` 模式已烧录并读回校验，峰值灰度 4096、GCLK 请求 1 MHz，每个 CTRL 约 1 ms 轮流选通。摄像头采集 480 帧，观察到全键盘白→蓝→红→绿的亮度升降和颜色间暗场；证据为 `build/camera-breathe/verification.jpg`。只验证全键盘统一颜色的共享灰度帧，逐键不同颜色与多 CTRL 同时选通仍未验证。

## 呼吸灯亮度高峰频闪修复

日期：2026-10-10。初版全键盘四色呼吸在单色接近亮度高峰时出现明显频闪，暗部较不明显。首次摄像头验证只确认四色和亮度变化，未充分验证频闪。

确认的代码问题：每次更新呼吸亮度都释放全部 CTRL，并由 `mbia045_send_frame()` 在整个软件串行发送期间停止 GCLK，导致每档更新出现一次全键盘黑场。亮度越高，黑场前后的绝对亮度差越大，越容易感知。另一个时序缺陷是软件 `delay_ms(1)` 选通没有与 MBIA045 的 S-PWM 子周期对齐，刷新还受串行发送阻塞，可能产生 PWM/扫描拍频；没有用示波器单独分离两种因素的贡献。

修复已实现并烧录：

- breathe 模式将 MSI 从约 2.097 MHz 提升至约 4.194 MHz，GCLK 请求 2 MHz，实际约 2.097 MHz；其他模式保持原来的系统时钟。
- SysTick 中断持续扫描八个 CTRL；每组选通 2048 个 CPU 时钟，即 1024 个 GCLK 周期，约 0.488 ms。名义全键盘刷新率约 256 Hz，取代原约 125 Hz 且受发帧停顿影响的软件扫描。
- `mbia045_send_frame_live()` 在当前画面继续显示时发送下一帧，只在最终 global latch 附近短暂停止 GCLK；该短临界区关闭中断，防止 CTRL 与 GCLK 的 GPIO 模式寄存器更新互相覆盖。
- 呼吸灰度量化为 64 的倍数，使 16 位 S-PWM 的 64 个 1024 时钟子周期重复同样的亮度，降低不同 CTRL 得到不同 PWM 片段的风险。保持 16 位灰度模式及原有驱动电流配置。
- 启动向量增加可覆盖的 SysTick 入口；构建链接 `libgcc` 的整数除法辅助函数。safe 与 breathe 模式构建均通过，修正版已烧录并读回校验。

依据：[MBIA045 数据手册](https://www.believesrl.com/system/uploads/attachment/data/7780/59426983/MBIA045_Datasheet_VA.00-EN.pdf)说明 16 位 S-PWM 拆成 64 个 1024 时钟子周期；[应用说明](https://www.believesrl.com/system/uploads/attachment/data/7868/2948308/MBIA045_Application_Note_VA.00-EN.pdf)要求 global latch 前停止 GCLK，并强调控制器同步 PWM 时序。

验证：SWD 暂停读取后恢复运行，确认 MSI range=6、TIM22 ARR=1、SysTick LOAD=2047。摄像头另采集 480 帧，四色与暗场正常。对 C 键局部画面的高亮区去除 9 帧移动平均趋势后，旧版/新版相对波动 RMS 分别约为：白 3.2%/1.1%、蓝 4.5%/1.6%、红 4.4%/1.8%、绿 5.3%/2.2%。这只是普通摄像头的比较指标，受曝光和采样影响，不是示波器测得的频闪指标。新版画面和亮度记录位于 `build/camera-breathe-fixed/`，旧版固件备份为 `build/test-breathe-before-fix.elf`。

用户实物确认：**“确实消失了”**。当前运行修正版全键盘白→蓝→红→绿呼吸。后续动画应保留持续扫描、后台发帧和 PWM 时序对齐，避免恢复“关全键盘→整帧发送→重新扫描”的更新方式。


## 三色斜向波浪测试

2026-10-10，根据用户描述复现左下→右上的斜向波浪，用户指定波峰红、黄、蓝。首版配置现保存在 `configs/effects/diagonal-wave-v1.json`：发波间隔 1600 ms、横穿时间 3200 ms、波峰渐亮 180 ms、变色尾光 1200 ms、峰值灰度 4096。尾光由当前波峰色混合到下一波峰色，并按平方曲线衰减；这不是原厂固件的精确逆向，观感仍待用户确认。

完整的 128 灯位记录保存到 `configs/keyboard/keymap.json`，其中 109 个已观测灯位参与渲染，其余保持零。位置投影使用照片坐标 `x-y`，最早为左 Ctrl，最晚为 Delete/Insert；同一宽键的多个灯位独立参与空间推进。

最初 MCU 逐灯计算渐变导致工作量超过选通周期；修正为电脑端生成 8 ms 采样的 RGB 查找表。逐组不同数据使用新的持续播放路径：在当前组显示期间准备和发送下一组的数据，等当前组完成一个 S-PWM 子周期后才停钟、释放 CTRL、global latch、选通下一组及恢复 GCLK。不会在每次动画更新时关闭整块键盘等待整帧传输。

逐键数据传输使用加速 GPIO 循环，保持原先实测的 MSB 顺序和最后一个数据位的 LE 单时钟锁存；硬件 SPI 路径没有保留。CPU 为 32 MHz（HSI16×4÷2），电压 range 1、Flash 一等待周期，GCLK 为 2 MHz。快速时钟下，默认低速 LE 边沿曾导致锁存异常，照片中仅 C/Space/音量减附近响应；将 PA4–PA7 设置快速边沿后，完整灯位恢复响应。后续提升 CPU/DCLK 时要同时核对 LE 的边沿与时序。

验证：最终波浪固件已烧录并读回校验，摄像头采集 180 帧，观察到不同位置的波峰移动、红黄蓝循环与变色消退的尾光。SWD 读取 CFGR=`0x0044000f`、TIM22 ARR=15；诊断最大工作量为 15396 个 CPU 时钟（约 481 μs），预算 16384 时钟（512 μs），`keyboard_wave_overruns` 为零。该计数覆盖观测期间，不能代替示波器检查；软件交接存在少量额外时间，刷新频率低于理想的 244 Hz。证据保存在 `build/camera-wave/`，包含汇总照片、代表帧、烧录与时序日志。

经典呼吸及 safe 模式重新构建通过，配置测试通过；本机没有 native C 编译器，C 曲线测试明确跳过。实测键盘当前运行波浪；要恢复经典呼吸，运行 `./test-keyboard.py --profile classic-breathe --flash`。

时钟与 GPIO 寄存器依据：[ST STM32L051 官方设备头文件](https://raw.githubusercontent.com/STMicroelectronics/cmsis-device-l0/master/Include/stm32l051xx.h)，PLL 配置依据：[ST 官方 RCC HAL 定义](https://raw.githubusercontent.com/STMicroelectronics/stm32l0xx-hal-driver/master/Inc/stm32l0xx_hal_rcc.h)。


### 第二版：减速与混色衔接

2026-10-10，用户确认首版基本形式正确，要求推进速度减半、波峰之间保留混色而非全黑。当前 `configs/effects/diagonal-wave.json` 的横穿时间改为 6400 ms，发波间隔同步改为 3200 ms，前沿渐亮改为 360 ms，保持空间波峰间距；尾光延长至 4800 ms。渐亮阶段叠加前一道波浪的混色尾光，并随新波峰渐亮将其淡出；到达波峰时只有当前颜色。波峰之后继续向下一色混合并衰减，循环交界连续。启动时尚未抵达的灯位仍保持关闭。

预计算表保留 8 ms 采样、64 灰度量化及原扫描时序。稳定循环中所有采样均有余光，最暗采样的最强 RGB 通道灰度为 384（峰值 4096）；这只是灰度值比例，不代表视觉亮度比例。回归检查覆盖减速比例、三种纯色波峰、混色、循环衔接和无全黑采样；首版配置仍可复现原来的暗场。9 项测试中 8 项通过，1 项因本机缺少 native C 编译器跳过。

新版已烧录、读回校验并运行；摄像头采集 240 帧，可见斜向移动以及波峰间的混色余光。SWD 诊断显示 7984 次全键盘扫描，最大准备耗时 15396 个 CPU 时钟（约 481 μs），扫描超时为 0。汇总照片、代表帧及日志保存在 `build/camera-wave-v2/`。具体观感待用户实物确认。


### 第三版：增强起伏与连续混色

用户反馈第二版峰谷差小、半波长偏长，且交界混色生硬。原因是尾光持续 4800 ms，使高亮区域宽；其颜色按尾光时长插值，到下一波前尚未完成换色，随后又在 360 ms 前沿中快速让位给下一单色波峰。

当前配置新增可选 `wave_curve: "smooth"`、`floor: 256`。旧配置仍采用原算法，第二版保存为 `configs/effects/diagonal-wave-v2.json`。第三版保持横穿时间 6400 ms，发波间隔缩至 2400 ms，空间波峰间距缩短 25%；峰值从 4096 提高至 6144。颜色按完整的波峰间相位，以整数 smoothstep 连续混合；亮度由到最近波峰的距离生成 smoothstep 肩部再平方，波峰到波谷宽度为 1200 ms。波峰时纯色，波谷保留少量混色余光，亮度与颜色在波峰、波谷以及循环交界均平滑收尾。`crest_ms: 240` 是波峰相位偏移，新的曲线宽度由 `tail_ms` 控制。

预计算采样显示三个波峰为纯红、纯黄、纯蓝，最暗处最强通道分别为 256、128、128；颜色过渡四分之一、四分之三处均有至少两个通道达到 192。相邻 8 ms 采样（包括周期接缝）每通道变化不超过 128。测试 10 项，9 项通过，1 项 native C 曲线测试因缺少本机 C 编译器跳过。固件构建及烧录读回校验通过。

实物验证：摄像头采集 160 帧，可见较窄高亮区、暗谷及紫色等混色衔接。SWD 记录 11477 次完整扫描，最大准备耗时 15369 个 CPU 时钟，扫描超时为 0；暂停读取后已恢复播放。照片与日志保存于 `build/camera-wave-v3/`，具体观感仍以用户实物观察为准。

随后用户反馈启动时远端黑区须等待波浪抵达，要求预填充。波浪播放器现在从不小于横穿时间的完整颜色周期起点开始，首组选通与后续扫描使用同一时间基准。当前红蓝黄模式使用虚拟起点 10800 ms，立即呈现各位置的稳态颜色，并按原节奏继续推进；亮度、曲线、颜色顺序及全部时间参数保持一致。此启动逻辑适用于 wave 播放路径。未映射灯位仍保持零。

配置与输出核对确认 109 个已映射灯位在初始画面均有颜色，最强通道为 2944..3072。回归测试 10 项通过，1 项因缺少 native C 编译器跳过；固件构建、烧录及读回校验通过。此次未采集实物启动视频。

用户随后要求再次加强混色。红蓝黄配置新增 `color_blend: 512`：将周期 B 样条的三个控制色权重以 50% 比例混向等权，主控制色最大权重从约 2/3 降为 1/2，仍保留循环换色。此参数仅用于 `color-flow-blended`，范围 0..1024，省略时保持原曲线。主机生成与 C 像素计算同步实现；原已保存配置保持原混色强度。

遍历当前红蓝黄配置的全部 1350 个采样，最弱 RGB 通道的全周期最低灰度从 64 提高到 640，最弱通道平均灰度约从 703 提高到 1124；最强通道逐采样保持一致，相邻采样最大通道变化仍为 64。颜色顺序、横穿时间、间隔、灰度参数和启动预填充保留。回归测试 11 项通过，1 项 native C 测试跳过；构建、烧录及读回校验通过。实物混色观感待用户确认。
